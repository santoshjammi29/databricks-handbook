## 2. Static Classification Heuristic & Known Limits

`handbook audit-content` parses each notebook's Python code cells with `ast.parse()` (ignoring `# MAGIC %md` cells and string literals) and evaluates:
- **Spark/Delta Execution**: Calls to `spark.createDataFrame`, `spark.range`, `spark.read`, `spark.readStream`, `spark.sql`, `DeltaTable`, or `chispa.assert_df_equality`.
- **Computed Assertions**: `assert` (or `assert_df_equality`) statements referencing Spark-derived variables rather than pure Python dictionary/string literals.
- **Workspace-Only APIs**: Calls to `dlt`, `dbutils`, `VectorSearchClient`, `databricks.connect`, or unmocked `system.*` tables.

**Known Heuristic Limits**:
1. Static AST analysis cannot prove semantic data correctness or catch runtime SQL/Spark errors — only executing `uv run handbook run-local --tier T2` (or `uv run pytest -m spark`) proves `T2` notebooks pass end-to-end.
2. Local Spark (`delta-spark 3.2`) runs without Unity Catalog, Photon C++, or Serverless SQL Warehouses, so `T3` features (Unity Catalog ACLs, `system.billing.usage`, DLT managed runtime) require a live Databricks workspace (`T3` currently stands at 0 workspace-verified runs without attached CI workspace secrets).
